邮箱

把「读取已配置上游邮箱的当前邮件」做成内置 MCP：按实例隔离、只读、正文限长、附件默认元数据。

问题自己接 IMAP平台 Mail 工具
接入成本自己写 IMAP 客户端、处理协议服务端配置上游，Agent 直接调用 MCP
登录态自己维护刷新与重连密码/签名密钥只在保存时写入服务端
大正文整篇灌进上下文，撑爆窗口正文有长度上限，超长截断
附件自动拉二进制默认只返回元数据（文件名/大小/类型）
多用户隔离自己实现token 绑邮箱实例，不能跨实例

功能清单

功能说明
按邮箱实例隔离每个 Mail 实例绑定自己的上游账户；token 只能读自己绑定的实例，插件只加载该实例的上游账户
真实邮箱与别名支持以真实邮箱或转发/别名邮箱查询；别名替换为实际来源邮箱并标注，避免误当主邮箱
正文长度控制正文超长截断，保护 Agent 上下文与计费
附件默认元数据不自动下载正文/二进制；需要内容时另行显式请求
只读不发送、不删除、不改邮箱状态
服务端配置上游「服务端配置」维护每个上游邮箱服务及其真实邮箱、别名邮箱

功能：token 绑实例，与 CDP 同构

能力绑定同构关系
Mail MCP token绑定邮箱实例，不能跨实例CDP token 绑 client
设备 token（device-control）绑定 device_iddevice-control
  • 外部 MCP 接入走 /mcp/mail/sse；用户侧写 Mail 明细后必须 resync，把新快照推给活着的 driver。
  • Agent MCP 身份：Agent 绑定用户后，所有鉴权 MCP 固定使用该用户已获授权的 token；未授权时 401。

配置流程

  1. 在「服务端配置」维护上游邮箱服务及其真实邮箱、重定向/别名邮箱；密码和签名密钥只在保存时写入。
  2. 在「邮件列表」输入可选邮箱地址实时查询，验证别名标注是否正确。
  3. 从 MCP 市场右上角「MCP 设置」创建共享 MCP 用户并分配服务；把 Mail 实例授权给需要用邮件的 Agent。
