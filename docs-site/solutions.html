1. 统一模型入口

对比项没平台（直连 Provider）用 Ai Lubricant
账号切换配额耗尽改代码里的 Key，重启，重新测试账号池自动切换，业务代码不动
多供应商每家一套 SDK、一套错误处理一个入口兼容 OpenAI / Anthropic / Responses
换模型改请求里的模型名，逐处排查管理端改路由映射，客户端模型名不变
故障处理自己写重试、冷却、切换逻辑连续失败降权、窗口熔断、九种冻结自动处理
排查依据只能看客户端报错请求日志显示每次尝试的账号、路径、Token、耗时

操作路径：

  1. 管理员在 /manager/channels 新增 Provider 渠道 + 账号池，测试认证、刷新模型列表。
  2. 在 /manager/model-routing 定义对外模型名，映射到候选渠道。
  3. 在 /manager/api-keys 创建 Key，限定可用模型与额度。
  4. 开发者把客户端 base URL 指向平台（见 API 接入）。

部署前提：数据服务 + PostgreSQL + Redis（部署文档）。

2. AI 开发与项目交付

对比项没平台（聊天窗口）用 Ai Lubricant
工作上下文每次对话从空白开始，代码靠粘贴项目工作区常驻，Agent 直接读写仓库
执行环境自己准备沙箱、装依赖任务派发到平台工作区或自有节点
命令执行复制到本地终端跑，结果再贴回去终端/编辑器在平台内，输出实时回传
多轮推进上下文超长就断，无法续接任务记录事件与产物，随时续接
提交身份Agent 用全局 Git 身份提交按用户/项目维护 Git identity

操作路径：

  1. 在 /console/projects 创建项目并关联仓库。
  2. 在项目内新建任务，写清目标/范围/验收/约束（见 任务写法）。
  3. 选模型和执行节点，提交后进任务详情看 Agent 事件与 diff。
  4. 完成后审查代码 diff 与测试输出，再决定合并。

部署前提：数据服务 + 前端，开启 compat_enabled；自有节点执行需先接入节点。

3. 自有机器执行

对比项传统 SSH 方案Ai Lubricant 节点
入网方向平台主动拨入机器，需要公网 IP / 端口映射节点主动出站连接，NAT 后可用
凭据管理分发 SSH Key，手动轮换撤销onboard 发 TOTP secret，AES-256-GCM 封存，一键 Revoke
端口暴露开放 22 端口，暴露攻击面不开任何入站端口
执行方式SSH 命令行，无统一审批审批后才调度，容量/角色可控
附加能力仅 shell同一连接复用：PTY 终端、host exec、文件、HTTP 代理出口

操作路径：

  1. 管理员在 /manager/nodes 点 Onboard，选 execution 或 management 角色。
  2. 在目标机器执行安装命令（含 node_id 与 secret，30 分钟内有效）。
  3. 回管理端核对身份后 Approve，节点上线。
  4. 开发者建任务时选该节点；或进浏览器终端直接操作。

部署前提：节点控制服务（python -m node_server）+ AGENT_COMPOSE_NODE_SERVER_PUBLIC_URL；主密钥持久化。详见 节点管理员手册。

4. 浏览器与邮箱自动化

对比项无头脚本 / 自接 IMAP平台内置工具
登录态临时实例无 Cookie，自己注入复用已登录的真实 Chrome
生命周期脚本跑完即销毁常驻，Agent 随时接管当前标签
操作方式写死在脚本里Agent 实时决定读页、执行 JS、切标签、截图
邮箱读取自接 IMAP，维护登录态与大正文只读 MCP 按实例隔离，正文限长、附件默认元数据
凭据隔离脚本持有全部凭据token 绑定具体 client/邮箱实例，不串台

操作路径：

  1. 用户在 /console/resources 创建 CDP 客户端或 Mail 实例，拿到绑定的 MCP token。
  2. 把资源授权给要用的 Agent。
  3. 管理员在 /manager/mcp-market 管理平台级工具与外部 MCP。

部署前提：CDP 需装 Chrome + MV3 扩展；Mail 需在服务端配置上游邮箱；外部 MCP 需服务可访问。

5. 私有化部署

对比项公有云 AI 服务私有化 Ai Lubricant
数据位置供应商控制自己的 PostgreSQL / Redis，执行在自己的节点
模型凭据绑定供应商自带任意 Provider Token，平台只做路由
审计与日志看供应商提供什么请求级日志、用量、审批、审计全在本地
运维责任供应商承担自己负责 DB、TLS、备份、升级（见 责任边界）

操作路径：

  1. 按 部署文档 拉代码、配 .env、docker compose up。
  2. 首次访问 /manager 完成管理员引导。
  3. 配置渠道、路由、API Key、节点，开始使用。

部署前提：自己的服务器 + PostgreSQL/Redis；模型 Token 自备并遵守供应商条款。
