编辑器

为每个项目提供可持续的工作环境：主流编码 CLI 接入、三种执行环境按需选择、浏览器内编辑器、终端与文件管理，都在同一个项目上下文里。

问题自己搭的方案平台编辑器
编码工具接自有渠道改每个工具的配置/代码适配中转只改 base URL，平台按客户端模板补齐协议与字段
工作上下文片段粘贴进聊天，每次从空白开始项目/任务/编辑器/文件共享同一工作区
执行环境换个平台就得重搭环境、迁移远程连接三种环境档位各按所需；系统环境接入现有的环境，无需迁移远程连接
任务并行同一目录跑多个任务互相污染每个 session 独立 runtime 进程，目录隔离
文件与终端自己开 SSH/SFTP浏览器内直接用，走节点受控连接
提交身份Agent 用全局 Git 身份Git identity 按用户/项目关联

功能：更多编辑器形态

能力行为
更新的编辑器支持除 Claude Code / Codex / OpenCode 外，新增 Cursor CLI（ACP）与 Gemini CLI 作为编辑器和 review 执行端；编辑器清单随节点上报的 editor capabilities 动态发现，自定义编辑器 Agent 可引入新形态
编辑器多选一同一项目可创建多个不同 provider 的编辑器并行工作，互不串工作区
分支模式创建编辑器时按 default / existing / auto 选择分支策略：用项目默认分支、指定既有分支、或自动开工作分支——同一项目可并存多个分支
资源随编辑器下发MCP、技能、插件、项目提示词按编辑器单独配置，编辑即生效

功能：三种执行环境

创建任务时先选环境档位（界面里对应「隔离环境 / 共用环境 / 系统内置」）——它决定编辑器会话跑在哪个 HOME 里、装好的东西归谁所有。三档的区别：

隔离环境共用环境系统环境
跑在哪每次任务新建的一次性 HOME，用完即回收你命名的持久 HOME，固定在创建它的节点上节点操作者的真实本机 HOME
复用什么什么都不带，每次干净开始技能 / MCP / 插件配置一次，装好的依赖与 CLI 登录态跨任务复用操作者已装的工具、登录态与配置目录原样可用
谁维护平台自动回收，零配置你在环境页维护期望集合，同步到节点；已装 / 待同步 / 多余一目了然节点操作者为主，平台可看清单、增量安装
适合默认档；并行任务互不干扰长期项目，工具链与登录态要积累接入现有的环境，无需迁移远程连接

一句话区分隔离是「每次重来」，共用是「你搭好反复用」，系统是「直接用操作者已经搭好的那台」。任务里临时取消某个资源只是那一次不激活，不会动共用环境本身。

系统环境：接入现有的环境，无需迁移远程连接

把一台已经配好的机器交给 Agent，传统做法要么把环境搬进容器沙箱（迁移即失真、登过的账号又得重来），要么自己搭 SSH 与远程连接（开端口、发密钥、NAT 后面还够不着）。系统环境两个都不要：节点装上即可，任务直接跑在操作者的真实本机 HOME 里——已装的 CLI、登录过的账号、~/.claude、~/.agents、~/.mcp.json 等配置目录原样可用。现有的环境长什么样，任务拿到的就是什么样。

行为说明
看得见节点扫描本机 HOME 并上报清单：技能 / 插件 / MCP，含版本、来源编辑器与 HOME 相对路径——系统环境的任务实际会拿到什么，一清二楚，不是黑盒
增量安装平台资源可装进本机 HOME；同名默认跳过，覆盖需显式勾选——不默认动操作者已有的东西
卸载有边界只能卸载平台装过的（节点按自己的安装清单复核，拒绝其余一切）；操作者手装的不受影响
凭据不落本机任务勾选的技能 / MCP 不会写入本机配置；每个任务的 MCP 凭据按任务私有下发，永不写进操作者的 ~/.mcp.json，多个任务共享同一环境也不会互串凭据
归档入库本机自有的技能 / 插件可一键打包归档为平台资源，其他节点与共用环境即可复用
开启方式宿主机安装的节点默认开启；容器节点默认关闭（容器里的 HOME 是镜像的，不是操作者的）。容器节点需要时，启动时设置 AGENT_COMPOSE_NODE_ALLOW_SYSTEM_ENV=on（或 --allow-system-env=on）后重启，节点会重新上报该能力位。未开启的节点，系统档会被拒绝派发。

系统环境的本机清单与安装/卸载/归档，在节点详情的「系统内置环境」Tab 操作；共用环境的配置在「环境」Tab。详见 节点管理员手册。

功能：代码 review

对比项人工 review平台自动 review
触发时机记得点才看项目 webhook 事件（如 PR）自动触发
执行者人挤时间你选的编辑器（Claude Code / OpenCode / Gemini CLI / Cursor CLI）跑隔离 review skill
方法论各看各的框架化（如 OpenCodeReview Delegate）：确定性 diff + 规则脚手架，编辑器负责推理
并发与限流排队每项目并发上限可配；review 单独的 RPM/Token/并发限额，不打爆生产额度

review 任务类型（develop / design / review）与子类型（pr_review / diagnose_bug 等）同样可以手动创建；自动 review 的框架、执行编辑器、节点与资源在项目的 review 设置里一次配好。节点需上报对应编辑器 CLI 的能力标签才参与 review 调度。

功能：项目、任务与工作区

能力作用
项目统一承载仓库、任务、编辑器、提示词与成员边界
任务记录目标、执行状态、Agent 事件、结果和 Token 用量
编辑器项目的工作环境与会话入口，归属项目而非孤立 IDE
终端与文件浏览器内操作工作区或节点 PTY；文件浏览编辑无需 SCP/SFTP
Git identity提交身份与用户/项目关联

功能：会话隔离

机制行为
session = 独立 runtime 进程工作目录相互隔离，任务并行不打架
任务子 Key 收窄可用模型、编辑器、策略与速率限制派生成收窄的子 Key，任务级不越权
Git 走服务端反向代理节点 clone 用签名 proxy URL，真实 PAT 只在服务端内存；token 绑任务、只读、任务结束即失效
运行时预检缺 agent 运行时时 create ack 直接拒绝；终态无条件落库

功能：节点接入即为工作区

旧笔记本、办公室台式机装上节点程序即可作为执行环境——NAT 后面也行，不需要公网 IP 或开端口。普通任务不独占节点，容量由节点侧 max_sessions 控制。详见 节点能力详解。

功能：手机发起与跟踪

手机上选项目、模型与节点发起任务，查看执行轨迹与产物。移动端适合发起、跟踪、复核，不替代桌面编辑器。详见 手机客户端详解。

怎么用

  1. 创建任务时先选执行环境（隔离 / 共用 / 系统内置），再填任务内容；系统档只有已开启的节点可派发。
  2. 从项目详情的「编辑器」Tab 创建编辑器，选工作节点与分支模式。
  3. 进入 /console/editor/:editorId，新建/恢复会话。
  4. 用完停止会话，释放节点容量。完整步骤见 开发者手册。
