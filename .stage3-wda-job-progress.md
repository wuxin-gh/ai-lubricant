# Stage 3 Server-Side Implementation: WDA Job Routes + Signing/Artifact Stores

## Completed (2026-09-04)

### 1. Database Schema (`server/db.py`)
**Added two iOS tables in `create_builtin_tool_tables`:**

**`ios_signing_profiles`** — 签名配置托管（App Store Connect p8 / 手动 p12+mobileprovision）
- `id BIGSERIAL PRIMARY KEY`
- `owner_user_id TEXT NOT NULL` — 归属用户
- `name TEXT NOT NULL` — 配置名称（用户可读标识）
- `kind VARCHAR(16) NOT NULL CHECK (kind IN ('asc', 'p12'))` — 签名方式
- `secret_data JSONB NOT NULL DEFAULT '{}'::jsonb` — 敏感字段（p8_key/key_id/issuer_id/team_id 或 p12_base64/p12_password/mobileprovision_base64）
- `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`
- Index: `idx_ios_signing_profiles_owner (owner_user_id)`

**`ios_wda_artifacts`** — WDA 产物库（预构建 .ipa 去重托管）
- `id BIGSERIAL PRIMARY KEY`
- `owner_user_id TEXT` — 归属用户（NULL = 全局共享产物）
- `name TEXT NOT NULL` — 产物名称
- `version TEXT NOT NULL DEFAULT ''` — 版本标识
- `sha256 TEXT NOT NULL UNIQUE` — 文件哈希（去重键）
- `size_bytes BIGINT NOT NULL DEFAULT 0`
- `storage_path TEXT NOT NULL` — 服务端存储路径
- `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`
- Indexes: `idx_ios_wda_artifacts_owner (owner_user_id)`, `idx_ios_wda_artifacts_sha256 (sha256)`

**设计原则**：
- 签名材料 `secret_data` 永不回显（GET 响应只返 id/name/kind/created_at）
- WDA artifact 按 sha256 去重（ON CONFLICT DO UPDATE），避免重复存储
- owner_user_id NULL 表示全局可见产物（管理员上传，所有用户可用）

### 2. Storage Layer (`server/ios_store.py`)
**Signing Profile CRUD:**
- `create_signing_profile(owner_user_id, name, kind, secret_data)` — 创建签名配置
- `get_signing_profile(profile_id, owner_user_id)` — 读取配置元数据（无 secret_data）
- `get_signing_profile_secret(profile_id, owner_user_id)` — 读取完整配置（含 secret_data，仅 job 调度时用）
- `list_signing_profiles(owner_user_id)` — 列出用户的所有签名配置
- `delete_signing_profile(profile_id, owner_user_id)` — 删除配置（owner-check）

**WDA Artifact CRUD:**
- `create_wda_artifact(owner_user_id, name, version, sha256, size_bytes, storage_path)` — 创建产物记录（sha256 冲突时更新元数据）
- `get_wda_artifact(artifact_id)` — 按 ID 读取产物
- `get_wda_artifact_by_sha256(sha256)` — 按哈希读取产物（上传去重用）
- `list_wda_artifacts(owner_user_id)` — 列出可见产物（用户自己的 + 全局共享的）
- `delete_wda_artifact(artifact_id, owner_user_id)` — 删除产物（owner-check）

### 3. User-Facing Routes (`monkeycode_compat/routes_ios.py`)
**签名配置路由：**
- `POST /api/v1/users/ios/signing-profiles` — 上传签名配置（校验必填字段：asc 需 p8_key/key_id/issuer_id/team_id，p12 需 p12_base64/p12_password/mobileprovision_base64）
- `GET /api/v1/users/ios/signing-profiles` — 列出用户的签名配置（不含 secret_data）
- `DELETE /api/v1/users/ios/signing-profiles/{profile_id}` — 删除签名配置

**WDA 产物路由：**
- `POST /api/v1/users/ios/wda-artifacts` — 上传 .ipa 文件（计算 sha256，存储到 `IOS_ARTIFACT_STORAGE_DIR`，去重）
- `GET /api/v1/users/ios/wda-artifacts` — 列出可见产物
- `GET /api/v1/users/ios/wda-artifacts/{artifact_id}/download` — 下载产物（节点调用）
- `DELETE /api/v1/users/ios/wda-artifacts/{artifact_id}` — 删除产物

**WDA Job 路由（完整实现）：**
- `POST /api/v1/users/ios/devices/{resource_id}/wda/prepare` — 发起 WDA 准备 job（获取签名材料 + artifact 元数据 → 构造 NodeIosWdaJob frame → 下发到 node）
- `POST /api/v1/users/ios/devices/{resource_id}/wda/renew` — 发起续期 job（复用证书 → 重建 profile → 重签 → 重装）
- `POST /api/v1/users/ios/devices/{resource_id}/wda/reinstall` — 发起重装 job（使用现有签名材料）
- `GET /api/v1/users/ios/devices/{resource_id}/wda/jobs/{job_id}` — 查询 job 状态（从 registry snapshot 轮询）
- `POST /api/v1/users/ios/devices/{resource_id}/wda/jobs/{job_id}/cancel` — 取消 job（下发 NodeIosJobCancel frame）

**路由注册**：已挂载到 `monkeycode_compat/__init__.py`（line 119 import + line 162 include_router）

### 4. Control Plane Job Dispatch (`node_server/service.py`)
**Added iOS WDA job methods:**
- `ios_start_wda_job(node_id, job_id, udid, device_id, action, artifact, signing_profile, wda_bundle_id, xctest_config_name)` — 构造 NodeIosWdaJob frame（含 signing secret + artifact download URL），初始化 registry job snapshot，下发并等待 ack（5s 超时）

### 5. Registry Job Snapshot (`node_server/registry.py`)
**Added job snapshot storage in `Connection`:**
- `_ios_job_snapshots: dict[str, dict]` — 内存 job 快照（job_id → {status, stage, percent, message, events[], ...}）
- `init_ios_job_snapshot(job_id, device_id, udid, action)` — job 派发时初始化快照
- `update_ios_job_snapshot_event(event)` — 收到 NodeIosJobEvent 时更新进度（保留最后 20 条 events）
- `deliver_ios_job_result(result)` — 收到 NodeIosJobResult 时更新终态（status=completed/failed, error_code, completed_at）
- `get_ios_job_snapshot(job_id)` — 查询快照（轮询端点）
- `clear_ios_job_snapshot(job_id)` — 清理快照（客户端确认完成后）

**Snapshot schema:**
```python
{
    "job_id": str,
    "device_id": str,
    "udid": str,
    "action": "prepare|renew|reinstall",
    "status": "running|completed|failed",
    "stage": "queued|downloading|signing|installing|...",
    "percent": int,
    "message": str,
    "retryable": bool,
    "error_code": str,
    "created_at": str,  # RFC3339
    "updated_at": str,
    "completed_at": str,
    "events": [{"seq": int, "stage": str, "message": str, "timestamp": str}],
}
```

## Security Boundaries Preserved
- 签名材料 `secret_data` 仅在 `get_signing_profile_secret` 返回（job 调度专用），常规 GET 永不回显
- Signing secrets 通过 TLS NodeConnect 一次性下发（不进日志/UI）
- WDA artifact 上传校验 .ipa 扩展名
- Artifact 下载校验 owner visibility（用户自己的 + 全局共享的）
- 所有操作 owner-check（`owner_user_id = str(user.id)`）
- Job 路由校验设备归属（`_owned_device` helper）
