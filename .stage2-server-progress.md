**Added iOS dispatch methods:**
- `_require_online_ios_host(node_id)` — gate: online + role=ios_host + ios_mgmt=true
- `ios_discover(node_id)` — trigger device enumeration
- `ios_claim_device(node_id, udid, device_label, pairing_code)` — dispatch claim + await ack (30s timeout)
- `ios_release_device(node_id, device_id, udid, delete_credential)` — dispatch release + await ack (10s timeout)

All methods follow the canonical dispatch-with-ack pattern (`await_ack` → `send` → `wait_for` → `cancel_ack` on timeout/error).

### 6. User-Facing Routes (`monkeycode_compat/routes_builtin_tools.py`)
**Added 4 routes (before `/resources/{resource_id}`):**

**`GET /resources/ios-hosts`** — list available ios_host nodes the user can access (filters `role == "ios_host"` from `list_my_nodes`)

**`GET /resources/ios-hosts/{node_id}/devices`** — retrieve cached device inventory (calls `get_ios_devices`, maps Connect codes to HTTP status)

**`POST /resources/ios-claims`** — claim flow:
1. Body: `{node_id, udid, label}`
2. Check `user_can_use_node(user.id, node_id)`
3. Conflict check: reject 409 if any existing device resource has `ios.udid == udid`
4. Mint pairing code (`dc_store.mint_pairing_code_for_owner`)
5. Dispatch `ios_claim_device` → await ack
6. Return `{node_id, udid}`

**`POST /resources/{resource_id}/release-device`** — release flow:
1. Retrieve owned device resource
2. Extract `ios.{node_id, udid}`, `device_id`
3. Call `ios_release_device(node_id, device_id, udid, delete_credential=True)` (best-effort; offline nodes pass silently)
4. Revoke the device resource (`builtin_tool_store.revoke_device`)
5. Resync device-control driver

## Security Boundaries Preserved
- Pairing code: one-time, 600s TTL, hash-only Redis storage, constant-time compare (reused existing `dc_store`)
- iOS dispatch methods gate on `role=ios_host` + `ios_mgmt=true` capability
- User routes gate on `user_can_use_node(user.id, node_id)`
- UDID conflict check prevents double-claim
- `delete_credential=True` on release so revoked devices can't reconnect
