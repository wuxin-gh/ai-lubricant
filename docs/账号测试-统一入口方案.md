# 账号测试 —— 统一入口函数方案（终版·待开工确认）

> 设计（你定的）：
> 1. 把主链路入口**抽成统一入口函数**，入参：客户端请求接口(path)、参数(body)、headers、渠道白名单、渠道黑名单等；
> 2. **正常请求**：HTTP 端点内先校验 api key，从 key 提取渠道白/黑名单，再调入口函数；
> 3. **测试**：额外传**账号白名单** + **is_test** 两个参数，直接调入口函数。
>
> 已确认决策：
> - **无"回退"**：白/黑名单一律由调用方显式传入，选账号层**不再从 api_key 内部推**（删除 [rate_limiter.py:3241](../rate_limiter.py#L3241) 那次推导）。
> - **`is_test`**（单一开关）：为真时 ①选账号不排除 冻结/disabled/冷却 的账号；②失败**不冻结、不打冷却**（不写健康度惩罚）；③**不重试**。
> - **dashboard 不排除测试**：测试就是正常请求，不关注来源，量也小。
> - **范围**：chat / responses / messages / **图片 / 视频 / TTS 全做**。
> - **前端**：测试弹框挪进"渠道编辑"新增**测试 Tab**；账号操作列**删测试按钮**。

`_tts_generation_with_retry`（TTS）三者结构平行，且**都调** `acquire_client_with_provider`

所以"白名单/账号白名单/is_test"的下传对三条是**同一套改动**。全部调用点仅此 3 处，均在本期范围内。

  - 成功分支 `record_account_success` / TTFT 记录（[main.py:2498](../main.py#L2498)）也跳过——测试不改健康度。
  - **落库 `_finalize_channel_attempt_log` 保留**（测试要看明细，且天然带 `router_request_path` 等全字段）。

### 改动 D：统一入口函数
**文件** `main.py`（与 `_chat_with_retry` 同层），拟：
```python
async def dispatch_entry(
    *,
    endpoint: str,               # 客户端接口 path（落库 endpoint / 判定 modality）
    body: dict,                  # 客户端参数
    headers: dict,               # 客户端 headers
    api_key: str | None,         # 已在端点层校验；测试传 None
    api_key_name: str | None,
    provider_whitelist: set[str],
    provider_blacklist: set[str],
    account_whitelist: set[str] | None = None,   # 测试专用
    is_test: bool = False,                        # 测试专用
    request_protocol: str = "openai",
    chat_method: str = "chat",                    # chat/chat_responses/chat_anthropic
    operation: str | None = None,                 # None=对话；image/video/tts_generation=媒体
    extra_kwargs: dict | None = None,             # 测试注入 client_preset 等
):
    """按 operation 分派：
       - 对话 → 组装 kwargs → _chat_with_retry(...)，返回 (stream, 生成器)
       - 媒体 → _media_generation_with_retry / _tts_generation_with_retry，返回 result dict
       统一在此做 _prepare_client_request_body / 模型&modality 校验 / kwargs 组装。"""
```
- 职责：把现 `chat_completions` [main.py:2005-2051](../main.py#L2005)、`_media_generation_endpoint` [main.py:3964-3996](../main.py#L3964)、`_tts_endpoint` 里"**校验后到调 retry 之前**"的共性准备段收拢进来。
- **不进入口**（留在 HTTP 端点）：`_extract_api_key` 校验、`get_api_key_provider_filter` 提取、`_acquire/_release_api_key_limit`、`_add_recent_log`/token 统计、Response 包装。→ 测试直接调 `dispatch_entry` 天然绕开这些。

### 改动 E：HTTP 端点改为薄封装
- `chat_completions`（[main.py:1997](../main.py#L1997)）：校验 key → `pw, pb = get_api_key_provider_filter(api_key)` → `dispatch_entry(endpoint=path, body, headers, api_key, provider_whitelist=pw, provider_blacklist=pb, chat_method="chat")` → 包 Streaming/JSON + 统计四件套。
- `/v1/responses`、`/v1/messages`：同理，`chat_method` 传 `chat_responses`/`chat_anthropic`，`request_protocol` 对应。
- `_media_generation_endpoint` / `_tts_endpoint`：同理，`operation="image"/"video"/"tts_generation"`。

## 四、验证与回归

- **行为不变性**：正常 chat/responses/messages/媒体在 `is_test=False`、`account_whitelist=None` 下，
  白名单数据源仍是 `get_api_key_provider_filter`（只是改由端点层取并显式传），结果等价；重试/健康度/统计全不变。
- **全绿**：`tests/test_retry_policy.py`、`tests/test_model_group_selection_strategy.py`、`tests/test_admin_channel_optimization.py`、`tests/test_admin_request_logs_ui.py`。
- **补测**：显式白名单生效；`account_whitelist` 只命中指定账号；`is_test=True` 能选中冷却/禁用账号且失败不冻结、不重试；测试落库带 `router_request_path`；媒体测试路径。
- **手工**：对**冷却中**账号发起 chat/图片测试 → 测得通、详情有请求路径、账号冷却状态不被改写。
